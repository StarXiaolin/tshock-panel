# TShock 管理面板

给 **泰拉瑞亚 TShock 服务器**（TShock 6.2.1 / 游戏 1.4.5.8）用的本地网页管理面板：
在浏览器里开服、改配置、看日志、发物品、管权限、备份存档。

- **零第三方依赖**：只用 Node.js 内置模块，不需要 `npm install`
- **零侵入**：不改 TShock 程序、不改存档格式；配置写回前自动备份
- **只监听本机**：`127.0.0.1`，不暴露到局域网
- **一套页面管完**：13 个页面，从开服到日常运维

![面板预览](TShockPanel/preview.png)

## 功能

| 页面 | 能做什么 |
| --- | --- |
| 仪表盘 | 服务器状态、一键启停、当前世界、在线玩家、服主认证码 |
| 控制台 | SSE 实时日志、命令下发、常用快捷命令 |
| 世界存档 | 枚举/新建/删除世界，启动指定世界 |
| 物品发放 | 物品库检索、前缀/数量/目标玩家校验后交给 TShock 的 `/give` |
| 世界事件 | 陨石/血月/入侵/下雨等，类型从 `worldevent` 帮助输出解析 |
| 传送点 | 读取 `tshock.sqlite` 的 Warps 表（需要 Node 22 的 `node:sqlite`） |
| 权限管理 | 用户组、权限节点增删、父组继承、通配符权限警告 |
| 玩家与封禁 | 在线玩家、封禁列表、用户账号、白名单 |
| 插件管理 | 插件列表、上传/删除插件、读写插件配置、APM |
| 服务器设置 | 逐项编辑 `tshock/*.json`（写前备份、保留未知字段）、SSC 初始物品、公告与规则 |
| 备份与还原 | 存档/配置备份与还原（还原前再自动备份一次）、回收站 |
| 外观 | 夜间/日间/高对比主题、自定义配色、字号/密度/图标大小 |
| 帮助 | 常见操作与版本信息 |

## 安装

本仓库**只包含面板本身**，不包含 TShock 服务器程序。

1. **下载 TShock 服务器**：到 <https://github.com/Pryaxis/TShock/releases> 下载
   `TShock 6.2.1 for Terraria 1.4.5.8` 的 Windows 包，解压到一个自己的目录。
2. **下载本仓库**：点右上角 `Code → Download ZIP`，解压后把 `TShockPanel` 文件夹和
   `启动管理面板.cmd` 放进上一步的服务器目录（和 `TShock.Server.exe` 同一层）。
3. **安装 Node.js 22 或更高版本**（<https://nodejs.org/>），然后双击 `启动管理面板.cmd`。

放好之后目录应该长这样：

```
TShock-6.2.1-for-Terraria-1.4.5.8-win-x64-Release/
├─ TShock.Server.exe
├─ tshock/                     ← 服务器配置与存档数据（原样保留）
├─ 启动管理面板.cmd             ← 本仓库
└─ TShockPanel/                ← 本仓库
```

浏览器会自动打开 `http://127.0.0.1:13087`；端口被占用时会自动顺延到 13088、13089…，
实际地址打印在面板的命令行窗口里。

> 每个页面的细节、常见问题、目录说明见 **[TShockPanel/README.md](TShockPanel/README.md)**。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows（`启动管理面板.cmd` 是批处理；核心代码跨平台，但没有做过 Linux/macOS 适配） |
| Node.js | **22 或更高**（「传送点」页依赖 Node 22 的 `node:sqlite`；低版本其他功能可用） |
| TShock | 6.2.1（对应 Terraria 1.4.5.8）。换大版本后部分接口大概率对不上 |
| 第三方依赖 | 无 |

## 安全说明

- 面板只监听 `127.0.0.1`，不接受外部连接；也**没有登录鉴权**，所以不要把它改成对局域网开放。
- `TShockPanel/panel.json` 里保存着 TShock REST 令牌和明文的服务器密码，**不要提交、不要分享**；
  本仓库的 `.gitignore` 已经排除它。
- 面板会改写 `tshock/config.json` 以打开 REST 接口（默认 `7878`），这是下发控制台命令的通道。
  REST 监听所有网卡，介意的话可以在面板设置里换端口并加防火墙规则。
- 备份、日志、回收站都在 `TShockPanel/` 下。关闭面板后服务器可以继续独立运行，
  但推荐先在面板里「停止服务器」再关窗口。

## 开发

```bash
node tools/run-tests.js
```

跑 30 套单测 + 2 项前端检查（不需要 TShock 服务器，几秒钟跑完）。
需要完整发布包才能跑的冒烟测试：

```powershell
powershell -File tools/smoke.ps1 -CompareTo before
```

代码结构：

```
TShockPanel/
├─ server.js          装配依赖 → 注册路由 → 监听端口（没有业务逻辑）
├─ lib/               服务层（22 个模块）：REST 客户端、配置读写、进程管理、备份、世界、权限…
├─ routers/           12 个路由模块，一个页面一组接口
├─ public/            前端（25 个文件）：无构建步骤的经典脚本 + 单一 style.css
└─ data/              物品库、权限目录等静态数据
```

架构约束：后端 `lib` 单向依赖、路由只负责 HTTP 形状；前端按职责拆文件但不打包，
`tools/frontend-check.js` 会守住“符号不丢失、action 都有处理分支”这两条底线。

## 版本号

采用语义化版本 `主版本.次版本.修订号`，标签形如 `v1.0.0`：

| 变更 | 版本 |
| --- | --- |
| 只修 bug，不加功能 | 修订号 +1（`1.0.1`） |
| 加页面/加接口，向下兼容 | 次版本 +1（`1.1.0`） |
| 破坏性改动（配置格式、要求的 TShock/Node 版本变了） | 主版本 +1（`2.0.0`） |

当前版本 `1.0.1`，与帮助页显示的版本号、`TShockPanel/server.js` 里的 `VERSION` 常量一致。
发版流程见 **[RELEASING.md](RELEASING.md)**，变更记录见 **[CHANGELOG.md](CHANGELOG.md)**。
