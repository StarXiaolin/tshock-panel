# 验证清单

## 0. 为什么不是 `dotnet build`

这个目录里**没有 C# 源码**：`TShock.Server.exe`、`ServerPlugins/*.dll` 是官方预编译产物，
本机也只有 .NET 运行时、没有 SDK。所以 `dotnet build` 在本项目没有可编译对象。

对被重构的 Node.js 面板，等价的“编译通过”定义为下面三层，全部通过才算可提交：

| 层 | 检查什么 | 命令 |
| --- | --- | --- |
| 静态 | 所有 JS 文件语法合法 | `node --check <file>`（`tools/smoke.ps1` 会自动跑全部） |
| 契约 | 23 个 HTTP 接口的状态码 + JSON 形状（字段名/类型）没变 | `tools/smoke.ps1 -CompareTo before` |
| 副作用 | 启动/关闭面板这一趟没有意外改写 `tshock/*.json`、`panel.json` | 同上（脚本内做 SHA256 前后比对） |

“形状”刻意不比较具体值（人数、时间戳、文件大小本来就会变），只比较字段是否
**少、多、改名、改类型**——正好对应重构要求的“对外行为不变”。

## 1. 标准流程

```powershell
# 1) 改动前录一次基线（每个窗口只需一次，除非接口本身合法地变了）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\smoke.ps1 -Record before

# 2) 改代码……

# 3) 改动后对比
powershell -NoProfile -ExecutionPolicy Bypass -File tools\smoke.ps1 -CompareTo before

# 4) 单元测试（新增模块时同步加一套，全部跑一遍）
for %f in (tools\*.test.js) do node %f

# 5) 前端有改动时：静态检查 + 启动级冒烟（需要面板先在 13087 跑着）
node TShockPanel/server.js --no-open   # 另开一个窗口
node tools\frontend-check.js
node tools\frontend-boot.js

# 6) 改过 public/style.css 时：主题令牌与对比度
node tools\css-theme.test.js
node tools\contrast.test.js
```

退出码：`0` 通过，`1` 失败，`2` 前置条件不满足（端口被占用 / 基线目录不存在）。

要点：

- 跑之前先关掉正在运行的面板，否则 13087 被占用会直接退出。
- 脚本会真的启动面板（约 3 秒），探测完自动 `Stop-Process`；不会启动 TShock 服务器本身。
- 形状文件落在 `tools/smoke/<name>/`，已在 `.gitignore` 中，不进仓库。
- 如果某个接口**本来就该变**（例如新增字段），要单独说明并重录基线，不能默默跳过。
- **`tools/smoke.ps1` 是 PowerShell 5.1 脚本，编辑后必须确保文件带 UTF-8 BOM**，
  否则中文串被按 ANSI 解析、整脚本语法报错（本窗口踩过两次）。

## 1.1 前端三个检查分别管什么

| 工具 | 抓什么 | 抓不到什么 |
| --- | --- | --- |
| `node --check` | 语法错误 | 运行时依赖缺失 |
| `frontend-check.js` | 脚本顺序错、跨脚本重复声明、基线符号被漏搬 | 函数内部逻辑 |
| `frontend-boot.js` | 脚本加载后 `boot()` 能否在真实接口上跑通 | 点击交互、视觉 |
| `css-theme.test.js` | 业务样式硬编码颜色、主题令牌缺失、var() 拼错 | 布局与阴影观感 |
| `contrast.test.js` | 文字与背景对比度不足 | 阴影/边框的视觉舒适度 |
| 真人点页面（第 3 节） | 一切 | —— |

三套主题的切换观感（尤其浅色模式的阴影、弹窗遮罩）仍属于“真人看”的范围。

本机 dsh 内置浏览器**自 2026-10-21 22:40 起可用**（补装 Electron 二进制，见日志 §7.5），
所以第 3 节可以由代理执行；只有需要开服的第 9、10 条仍建议用户亲自做
（会真的拉起 TShock 服务器）。


## 2. 这套验证覆盖不到什么

- **前端交互**：`app.js` 的任何改动，形状对比完全无感。必须按第 3 节手动走一遍。
- **需要 TShock 正在运行的接口**：`/api/players`、`/api/groups`、`/api/bans` 在没开服时
  只会返回 400「服务器没有运行」，能验证错误契约，验证不了成功路径。
- **写操作**：`POST /api/config`、`/api/sscconfig`、`/api/text` 等会改文件，冒烟测试不碰它们
  （只在第 3 节手动测试，且测前先备份）。

## 3. UI 改动的手动验证清单

2026-10-21 22:40 已按本清单实走1–8 条（结果见日志 §7.5）；9–10 条需要开服，待用户演练。

重构 `public/` 下任何文件后，至少走完这几条（面板正在运行、服务器未启动即可走前 8 条）：

1. 打开面板首页，仪表盘显示“服务器未运行”，日志区在滚动。
2. 左侧切换 8 个页面各一次：控制台、世界存档、物品发放、世界事件、传送点、权限管理、玩家与封禁、插件管理、服务器设置、备份与还原、外观、帮助。
3. 「外观」切三套主题（夜间/日间/高对比度），确认标题、正文、按钮、输入框都跟着变、没有残留深色块。
4. 字号缩放拖到 125%，确认布局不溢出。
5. 「物品发放」搜 `天顶剑`、`Zenith`、`4956`，都能出下拉；按 `Esc` 能关。
6. 「服务器设置」随便改一个开关，点保存，看是否弹出确认/失败提示；**不要点重启**。
7. 「世界存档」列表能列出世界名（不是文件名），点「备份」能生成一条备份记录。
8. 浏览器控制台（F12）无红色报错。
9. （需要开服）点「启动服务器」，仪表盘进入运行态，在线玩家列表能刷新；再点「停止服务器」。
10. （需要开服）控制台输入 `say 测试`，能回显 TShock 的原始返回。

任何一条走不通就是回归，按 `git revert` 处理，不要“顺手修”。
